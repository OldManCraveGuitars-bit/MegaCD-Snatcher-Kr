# v0.776 — 미카 접수처 메뉴 번역 수정

정커 본부에서 미카가 있는 장소를 가리키는 **FRONT를 “접수처”로 수정**했습니다. 사용자의 최종 지정에 따라 “프론트”가 아닌 “접수처”로 표기합니다.

**보이스 자막에는 전용 Genesis Plus GX 코어가 필요합니다.** 이번 동봉 Windows·Android·Linux 코어는 v0.775 r48과 같은 파일이며, 자막 시각·화면 합성 기능을 바꾸지 않았습니다. RetroArch 본체와 APK는 수정하지 않습니다.

## 수정 범위

| 항목 | 이전 표기 | 수정 | 메뉴 연결 |
| --- | --- | --- | ---: |
| SP08.BIN/0029 — 본부 이동 메뉴 | 전면 | 접수처 | 5개 |
| SP21.BIN/0027 — 이후 본부 이동 메뉴 | 전면 | 접수처 | 1개 |
| SP33.BIN/0015 — 후반 본부 로비로 이동 | 앞쪽 | 접수처 | 1개 |

원본 메뉴와 인접 대사를 대조했습니다. SP33의 선택 다음 대사는 로비를 확인하자는 내용입니다. 반면 SP07은 폐허에서 막힌 앞길을 조사하는 메뉴, SP32는 터널 전방을 보는 메뉴여서 기존 “전면/앞쪽”을 유지했습니다. 물체를 가리키는 FRONT POD와 다른 문장 속 방향 표현은 이번 수정 대상이 아닙니다.

전체10,728항목 중3항목만 수정하고 나머지10,725항목은 그대로입니다. 각 모듈의 기존 빈 공간에 새 글자를 넣고7개 메뉴 참조만 연결하여 다른 문장·폰트·보이스 자막 데이터의 위치와 내용을 유지했습니다. 전용 코어·음성·오프닝 타이밍도 불변입니다.

## 업데이트 방법 — 이번에는 게임을 다시 패치해야 합니다

**v0.775 코어만 교체해서는 이 수정이 적용되지 않습니다. 게임 BIN이 변경됐습니다.**

1. `MegaCD-Snatcher-Kr-v0.776-Windows-Patcher.zip`을 풀고 `SnatcherKRInstaller.exe`를 실행합니다. 단독 EXE도 같은 파일입니다.
2. 아래 해시의 미국판 **원본** `Snatcher (USA).bin`을 선택합니다. 이미 패치한 BIN에 덧씌우는 방식은 지원하지 않습니다.
3. 이미 존재하는 빈 출력 폴더를 고릅니다. 약700MB 이상 여유 공간을 준비하세요. 원본과 기존 동명 파일은 덮어쓰지 않습니다.
4. 생성된 `Snatcher-KR-v0.776.bin`과 `Snatcher-KR-v0.776.cue`를 함께 보관하고, RetroArch에서 **CUE**를 엽니다.
5. 플랫폼에 맞는 전용 코어를 사용하세요. **v0.775 r48 코어가 있으면 그대로 사용 가능**합니다. 이전 코어 사용자는 동봉 코어로 교체하세요.

| 플랫폼 | 동봉 코어 |
| --- | --- |
| Windows x86_64 | `genesis_plus_gx_snatcher_kr_libretro.dll` |
| Android ARM64 | `genesis_plus_gx_snatcher_kr_libretro_android.so` |
| Linux x86_64 | `genesis_plus_gx_snatcher_kr_libretro.so` |

Android SO와 Linux SO는 서로 호환되지 않습니다. BIOS는 사용자가 별도로 준비합니다. 세이브스테이트에는 옛 메뉴 데이터가 남을 수 있으므로 **게임 재시작 후 게임 내 저장**으로 이어 하세요. 저장 파일은 먼저 백업하고, 내용 경로/파일명 변경 시 RetroArch의 저장 연결 설정을 확인하세요. 모든 저장 상태 호환성을 보증하지는 않습니다.

Windows 없이 적용할 때는 BPS 지원 패처에서 동일 원본에 `Snatcher-KR-v0.776.bps`를 적용합니다. 결과를 `Snatcher-KR-v0.776.bin`으로 이름 붙여 이번 CUE와 같은 폴더에 두고, 결과 해시를 확인하세요. 구형 BIN과 새 CUE만 섞으면 안 됩니다. [전체 사용법과 기존 실제 화면 갤러리](https://github.com/OldManCraveGuitars-bit/MegaCD-Snatcher-Kr/blob/v0.776/README.md)를 제공합니다.

## 확인 결과

- 실제 최종 게임의 M68000 메뉴 등록·복사 루틴을 분리 실행해 **7참조 × 6메뉴 위치 = 42조건**에서 새 문구와 종료 문자 복사를 확인했습니다. 모듈 데이터에 쓰기 없음도 확인했습니다. 분리된 CPU 실행이며 전체 게임 장면 재플레이나 새 스크린샷 확인으로 확대하지 않습니다.
- 관련 자동시험 **33개 통과**: 문구 연결, 잘못된 입력/메모리 영역 거부, 설치, 텍스트 편집기 검사.
- 전체 **265,813개 원시 섹터**를 대조해 대상3모듈 안의9개만 변경, 나머지265,804개(음성 포함) 불변. 변경 섹터 EDC/ECC와 기존 파일 크기·디렉터리·트랙 배치 유지 확인.
- BPS2회 생성 결과 동일 및 독립 적용 검사 통과. **완성된 EXE 자체**를 원본에 적용해 출력 **11/11파일**의 크기·SHA-256·CRC32 일치와 원본 불변을 확인했습니다.
- 코어3종·전체소스ZIP·빌드기록은 v0.775와 바이트 동일합니다. Linux 코어의 빌드/동적로드/API1 이력은 [Actions 38495067876](https://github.com/OldManCraveGuitars-bit/MegaCD-Snatcher-Kr/actions/runs/38495067876)에 있습니다. CORE-BUILD/CORE-REPRODUCTION의 v0.775 표기는 이 코어의 실제 빌드 버전을 뜻합니다.
- v0.775의 신규13트랙·427쪽 및 타이밍 교정, 승인된 오프닝·PCM·흰 글자와 밀착 검은 테두리를 유지했습니다. 이미 해결된3인 초상화 반복검사나 전편 재플레이는 하지 않았습니다.

Android 실사용·Linux 실제 게임·실기 Mega CD·전편 사람 청취 승인 등 기존 한계는 유지됩니다. 이번에는 제보된 장소명 수정과 필요한 연결·보존·설치 검사에 집중했습니다.
