# MegaCD-Snatcher-Kr — v0.77 시험판

메가 CD 미국판 *Snatcher*의 한국어 패치입니다. 게임 속 문구·선택문뿐 아니라 **음성에 맞춰 표시되는 한국어 자막**을 중점적으로 다룹니다. 자막은 게임의 페이지 넘김과 별도로 음성 진행을 따르도록 만든 **전용 Genesis Plus GX 코어**에서 그립니다. 화면 아래쪽의 흰 글자·검은 테두리 방식이며, 별도의 큰 검은 자막 상자를 만드는 방식이 아닙니다.

> **중요: 일반 Genesis Plus GX 코어만으로는 보이스 자막이 나오지 않습니다.** 이 배포판과 짝을 이루는 개조 코어를 반드시 사용하세요. 게임 BIN만 패치한 뒤 기본 코어에서 실행하는 것은 지원하는 완성 구성으로 간주하지 않습니다.

이 저장소와 배포 파일에는 원본 게임 이미지, 패치 완료된 전체 게임 이미지, BIOS, RetroArch APK가 없습니다. 본인이 보유한 정확한 미국판 BIN과 별도 BIOS가 필요합니다. 비공식·비상업적 팬 프로젝트이며 Konami, Sega, Libretro와 제휴하지 않았습니다. **v0.77은 시험판**입니다. 번역 목록과 추가 음성을 대조했지만, 전편 모든 분기 플레이나 사람 번역가의 최종 승인, 모든 기기의 동작 보증을 뜻하지는 않습니다.

## v0.77 변경 사항

- 처음 폐허로 이동할 때 빠졌던 **길리언의 독백4문장**을 복원했습니다. 해당 음성은 기존 PCM 자막 목록이 아니라 별도 CD 오디오 Track20에 있었습니다.
- 추가 조사에서 찾은 **13개 CD 음성 트랙에 자막426쪽**을 추가했습니다. 본부 귀환, 랜덤 등장, 병원 관련 통화, 차량 추격, 해리, 국장 전투 후, 제이미 통화, 미카와의 작별, 탑승 안내·마지막 작별, 폐허 독백, 병원 지하 대화 등을 포함합니다. 쪽수는 문장 수가 아닙니다.
- 자막은 **CD 음성의 재생 위치**를 따릅니다. 화면 넘김과 별개로 동작하며, 게임 메모리나 그래픽 타일을 덮지 않는 기존 최종 화면 합성 방식을 사용합니다. 흰 글자·밀착 검은 테두리 외 영역은 투명합니다.
- v0.76의 말투·문맥 교정과 제이미 이별의 “잘 안 들려!” 복원, 승인된 오프닝 시각은 그대로 유지했습니다. 기존 엔딩5줄 문구는 중복 하단 자막을 만들지 않습니다.
- **게임 BIN/BPS는 v0.76과 동일하고 전용 코어가 r47로 바뀌었습니다.** 아래 결과 BIN 해시와 일치하는 v0.76 사용자는 플랫폼에 맞는 **v0.77 코어만 교체**하면 됩니다. v0.75 또는 다른 BIN은 원본에서 다시 패치하세요. 기존 세이브스테이트 호환성은 보증하지 않습니다.

이전의 “고유 음성1,119개 전체 검수”는 **당시 등록된 PCM 목록의 검수**였으며, 원본 게임에 별도로 들어 있는 모든 CD 음성의 누락 검증은 아니었습니다. 이번에 그 범위 밖의 누락을 보완했습니다. 상세 내용은 [v0.77 변경·검사 기록](docs/RELEASE-v0.77.md), 이전 말투 교정 이력은 [v0.76 기록](docs/RELEASE-v0.76.md)에 있습니다.

## 받기 전에 확인할 것

1. [v0.77 릴리스](https://github.com/OldManCraveGuitars-bit/MegaCD-Snatcher-Kr/releases/tag/v0.77)에서 `SnatcherKRInstaller.exe` 또는 같은 EXE가 든 ZIP을 받습니다. **Windows 64비트용 패처**이며 APK 생성기나 RetroArch 수정 도구가 아닙니다.
2. 본인이 보유한 미국판 원본 `Snatcher (USA).bin`을 준비합니다. 파일 크기 **625,192,176바이트**, SHA-256 **`8d6f4dba8d9ce59991be9f65635047adc3b0f37ea2358f8c48b251883c9e55b6`**, CRC32 **`3faf807d`**만 입력으로 받습니다. 다른 덤프·다른 리전·이미 수정된 BIN은 거부합니다.
3. 결과를 넣을 **이미 존재하는 빈 폴더**를 준비합니다. 약 **700MB 이상**의 여유 공간이 필요합니다. 패처는 동명 파일을 덮어쓰지 않습니다.

## 패처 사용법

1. ZIP으로 받았다면 압축을 풀고 `SnatcherKRInstaller.exe`를 실행합니다. Windows 보안 경고가 뜨면 발행자와 [아래 SHA-256](#sha-256-검증)을 확인한 뒤 본인이 실행 여부를 판단하세요.
2. **원본 BIN 선택**에서 위의 `Snatcher (USA).bin`을 지정합니다. 패처가 크기·SHA-256·CRC32를 확인합니다.
3. **결과 폴더 선택**에서 빈 폴더를 지정하고 설치를 누릅니다. 패처가 BPS를 적용한 뒤 출력 BIN과 동봉 파일의 해시를 확인합니다. 실패하면 원본 BIN은 바뀌지 않습니다.
4. 결과 폴더에서 `Snatcher-KR-v0.77.bin`과 `Snatcher-KR-v0.77.cue`를 **함께 보관**합니다. RetroArch에서 게임을 열 때는 **`.bin`이 아니라 `.cue`**를 선택하세요. 이렇게 해야 CD 오디오 트랙 참조를 유지할 수 있습니다.
5. 사용하는 플랫폼에 맞는 **전용 코어**를 설치·선택하고 게임 `.cue`를 엽니다. 일반 코어로 열면 한국어 보이스 자막 기능이 빠집니다. BIOS는 RetroArch 안내에 따라 사용자가 별도로 설정해야 합니다.

### 플랫폼별 코어

| 플랫폼 | 전용 코어 파일 | 상태 |
| --- | --- | --- |
| Windows x86_64 | `genesis_plus_gx_snatcher_kr_libretro.dll` | 패처가 함께 출력합니다. Windows 실행·출력 해시 검증을 수행했습니다. |
| Android ARM64 | `genesis_plus_gx_snatcher_kr_libretro_android.so` | 패처가 함께 출력합니다. APK는 수정하지 않습니다. 실제 Android 기기의 코어 로딩·게임 재생은 아직 미검증입니다. |
| Linux x86_64 | `genesis_plus_gx_snatcher_kr_libretro.so` | 패처가 함께 출력하고, 릴리스에서 단독으로도 받을 수 있습니다. Ubuntu 24.04 x86_64에서 빌드·ELF/의존성·동적 로드/libretro API 검사를 통과했습니다. 게임 재생은 미검증입니다. |

Windows에서는 출력된 DLL을 RetroArch의 사용자 코어 위치에 복사하거나 코어 파일을 직접 불러옵니다. Android에서는 출력된 ARM64 SO를 기기로 옮긴 뒤 기기 RetroArch에서 외부 코어 설치/가져오기 기능을 사용합니다. Linux에서는 Linux x86_64 SO와 같은 이름의 `.info`를 코어 및 코어 정보 위치에 두거나 해당 SO를 직접 불러옵니다. 버전·배포 방식에 따라 메뉴 이름과 코어 경로가 다를 수 있으므로 설치된 RetroArch의 안내를 확인하세요. Android용 SO를 Linux용으로, Linux용 SO를 Android용으로 바꿔 쓸 수는 없습니다.

패처는 게임 BIN/CUE, Windows DLL, Android ARM64 SO, Linux x86_64 SO, 코어 정보 `.info`, 코어·폰트 라이선스, 개조 코어의 전체 소스 ZIP과 빌드 기록을 한 폴더에 출력합니다. 원본 BIN, 기존 파일, RetroArch 설치본은 덮어쓰지 않습니다.

### Windows 없이 수동 적용하기

Linux/Android만 사용하는 사람을 위해 릴리스에 `Snatcher-KR-v0.77.bps`, 결과용 `Snatcher-KR-v0.77.cue`, 플랫폼별 전용 코어도 개별 자산으로 제공합니다. BPS 지원 패처에서 **위 해시의 원본 BIN → BPS → 새 결과 BIN** 순서로 적용하세요. 결과 BIN 이름을 `Snatcher-KR-v0.77.bin`으로 맞추고, 릴리스의 `Snatcher-KR-v0.77.cue`와 같은 폴더에 두세요. CUE 안의 `FILE` 지시문이 이 BIN을 가리킵니다. 결과 SHA-256이 아래 값과 일치해야 합니다. 이 경로에서는 전용 코어도 별도로 받아야 하며, 원본·결과 게임 자체는 릴리스에 없습니다.

이미 v0.76 결과 BIN 해시가 일치한다면 기존 BIN/CUE 이름을 그대로 두고 코어만 교체해도 됩니다. 새 v0.77 CUE만 기존 이름의 BIN 옆에 두면 파일명이 맞지 않아 열리지 않습니다. 이름을 바꾸려면 BIN/CUE를 함께 맞추세요. 코어 교체 전 게임을 종료하고, 새 코어로 다시 실행하세요.

## 확인 범위와 알려진 제한

- **최종 v0.77 EXE 자체**의 페이로드 검사와 625,192,176바이트 원본 BIN 적용 시험을 수행했습니다. 결과11/11개 파일의 크기/SHA-256/CRC32 일치, 원본 파일 불변을 확인했습니다. 게임 BIN/BPS는 이전 전체 섹터·독립 적용 검사를 통과한 v0.76과 동일합니다.
- 새 CD 자막 소비처의13트랙151,169섹터·426쪽을 컴파일한 실제 C 코드로 검사했습니다. 두 픽셀 바이트순서, 재생 중지/탐색/음소거/트랙 불일치, 페이지 경계, 투명 영역 및 게임RAM 불변을 확인했습니다. 변경 표적 자동시험19통과. 이는 전편 게임 실행이나 사람의 음성 청취 검사가 아닙니다.
- Windows 정상 경로로 첫 폐허까지 진행해 새 독백4/4문장의 실제 표시와 자막 전후 비표시를 확인했습니다. 녹화 음성의 원음 정렬과 별도로 같은 실행의 원본 해상도 캡처4/4에서 흰 글자·검은 테두리 픽셀을 대조했습니다. 추가13트랙 전체를 플레이한 결과는 아닙니다.
- 기존 본문10,728개·폰트38개·PCM29모듈 및 기존 오프닝/회상 자산과 시각은 유지됩니다. 오프닝2 이별3장의 기존 정상속도 녹화 확인 이력도 유지됩니다. 장면에 따라 자막이 초상화 위에 겹칠 수 있습니다.
- 추가 대사는 원음의 기계 전사·단어 시각과 문맥을 대조했습니다. 일부 불확실 구간은 더 큰 모델로 재확인했지만 같은 모델 계열의 분석이며, 모든 문장을 사람이 직접 청취 승인한 것은 아닙니다. 미등록 PCM16자산은 검색한 원본 ISO99파일에 재생명령 참조가 없어 임의 연결하지 않았습니다. 이것만으로 절대적인 미사용이나 모든 누락 해결을 보증하지 않습니다.
- Android 기기 실사용, 실기 Mega CD, Linux 코어의 실제 게임 재생은 별도 검증이 필요합니다. 해당 결과가 나오기 전까지 검증 완료로 표기하지 않습니다.
- Linux v0.77 코어의 소스 해시 검증·빌드·ELF/의존성·동적로드/API1 검사는 [빌드 기록](https://github.com/OldManCraveGuitars-bit/MegaCD-Snatcher-Kr/actions/runs/38457704182)에 남겨 두었습니다.
- 문제가 발생하면 게임 화면, 사용 플랫폼·코어 파일 해시, 원본 BIN SHA-256, 해당 장면과 재현 순서를 함께 남겨 주세요. 원본 게임/BIOS 파일은 첨부하지 마세요.
